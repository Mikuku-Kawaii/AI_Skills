# ui-state-feedback

## 设计融合：完整状态来自实际协议

从真实请求协议推导加载、空态、无匹配、部分成功、取消中、失败与结果未知，不因为演示视觉需要而合并它们。骨架适合结构已知的首次加载，后台刷新保留可用内容；微小操作可用现有轻量进度，不能全局禁用 spinner 或强制骨架。

反馈使用主动语态、具体原因和可行下一步，错误不能只写“Oops”或泛化成功；字段错误贴近字段，全局或后台错误沿现有通知／详情分层。展示中的计数增长、打字和进度条不得暗示真实处理进度，也不能把动画结束当作提交成功。

方法参考：[Elaya AI Design Skills](https://github.com/elayadesign/ai-design-skills/tree/38bbe5765600b9178b5395a823c9f6c8d2b8e730)；以上为面向本技能的适配，现有项目契约与用户明确要求优先。

## 输入与前置检查

从仓库根读取 AGENTS.md、apps/web/AGENTS.md 和 [设计系统](../../../docs/ui/DESIGN_SYSTEM.md)，只加载本次相关规范。读取真实 API 状态、请求取消能力、写操作确认与表单状态所有者。

## 执行

建立首次加载/刷新/空/无匹配/失败/离线/部分/阻塞矩阵；首载 Skeleton，刷新保留内容；错误保留输入；仅开放已有重试取消能力。

按钮状态遵循设计系统“按钮外观与用途分离（2026-10-09）”：pending／disabled 不改变 filled／ghost 类别或升级主要用途，状态文字与加载图标复用稳定槽位，避免宽高跳动。pending 暴露 aria-busy 并阻止重复提交；取消仍是独立操作，只在真实可取消时开放，不因整个操作组 pending 被误禁用。普通按下不等于持久选中，不能用成功色块替代真实保存回执。

失败保留输入和上下文；唯一恢复入口可用有底按钮突出，但未知写入先核对原结果，不把“重试”绑定成盲目重发。弹窗取消通常透明普通、主要确认有底主要、最终危险确认有底危险；外观不得改变原确认、防重入或关闭协议。当前 Button 已支持 appearance／tone，复用真实接口，不为状态反馈重建按钮体系。

## 配置的生效与草稿

设置任务结合 [ui-settings-design](../ui-settings-design/SKILL.md)，先明确即时提交、编辑草稿、保存中及已确认值的区别。Switch 仅表达真实即时开关，保存型布尔字段保持显式表单语义；不能换控件后自动提交。行内重置与全组重置使用既有提交边界，恢复默认不自动等于已保存。

切分类不销毁未保存草稿；首载失败／畸形响应不能伪造成可提交默认值，无效配置保留输入并关联校验，结果未知先核对回执。禁用／处理中／失败仍有可辨状态和现有恢复入口。危险确认按实际影响使用，不为普通读取或取消草稿新增确认；秘密字段显隐不写日志、不触发保存。

## 状态文案与可用动作

原生 progress 与全局活动条使用共享 progress-track／progress-fill，核验浏览器轨道和填充实际颜色，不能只设置 accent-color。未知总量省略 value，不造百分比；减少／关闭动效仍有可访问状态与可见静态条。成功、部分成功、失败按真实语义覆盖，强制颜色沿系统配对。数值和浅深配对只在设计系统与 tokens.css 维护。

后续颜色实施遵循[冷铂灰蓝的角色与状态配对](../../../docs/ui/DESIGN_SYSTEM.md#platinum-gray-blue)：info／主动作可用灰蓝，成功、警告、失败／危险保留独立语义色和文字。基色用于文字与用于底色是两种配对，不能直接互换；warning 不表示普通进行中。pending 保持原按钮配对，disabled 不使搜索框或整组控件透底；状态值仅在共享 Token 派生，不能由页面自行加亮蓝或透明红层。

按设计系统的[文案与状态规则](../../../docs/ui/DESIGN_SYSTEM.md#ui-copy-interaction)，用实际阶段命名动作和反馈；“正在取消…”不等于“已取消”，“已登记”不等于“已处理”，“预览方案”不等于“开始执行”。优先在原控件槽或任务详情更新，刷新保留旧内容，不为每次读取弹出通知。阻止的是重复提交，不是连取消／查看详情／安全导航一起禁用。

空态先区分未添加、无匹配、无权限、未加载和失败，只给必要的一句结论与现有可用入口；不强制每处三段式说明。错误用可理解的现象与可执行下一步，经核对的 hint 放通知／详情；技术信息脱敏后才可复制，不直接展示 SQL、内部结构体或签名 URL。来源不明的建议不能自动生成修复命令，未知副作用仍只核对。

## 错误与状态的展示位置

按设计系统“主界面精简与反馈分层”选择反馈：主动操作的普通失败用不占文档流的简短通知并提供“查看详情”；需要立即决策的阻塞或既有危险确认进入 Dialog；后台／批量失败在任务入口汇总，由用户打开详情。不要每项失败弹一个模态框，不因轮询、重渲染或切页反复通知同一事件。

主界面不新增常驻错误段落、顶部告警条或撑高卡片／侧栏的堆栈；利用已有稳定状态槽表达失败／未知及详情入口。尚无内容可用时在原内容容器内显示简短失败占位，不能画成“无数据”或假成功。通知关闭不等于错误解决、取消完成或授权重试，原因、对象、回执和恢复动作仍从任务／详情入口找回。

详情弹窗先给用户可理解的原因和下一步，技术详情折叠并可复制脱敏诊断；不暴露密钥。长错误在弹窗内部滚动，主内容尺寸、滚动和草稿保持。字段错误保留 aria-invalid 与关联提示，主区用现有控件槽和可键盘打开的浮层；编辑弹窗／设置表单可在其内部显示必要校验文本，不把错误插入主工作区布局。未知副作用只提供核对，不自动重发。

## 禁止事项

禁止模拟百分比、把文件存在说成推理就绪、刷新重放写操作或记住危险确认。 维护原文件、公共 API 和人工元数据边界，不自动委派开发任务。

## 产物与验收

状态矩阵、共享反馈组件与重入/刷新测试。 用户可见变化原位同步 README；待办留在 TODO，完成记录归 LOG。失败可诊断；未知不成功；后台保留输入；维护/迁移确认仍有效。
