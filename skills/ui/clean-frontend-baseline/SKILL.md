# 干净前端初版基线

用于在缺乏成熟设计系统时拉高初版界面的工程与视觉下限，集中消除 AI 生成前端的典型通病：嵌套套娃卡片、冗余口号与解释废话、高饱和渐变堆积以及易碎的多级菜单交互。

- **适用边界**：新建 Web 应用、管理后台、工具工作区或桌面端页面初版构建。若项目已有成熟品牌系统、Design Tokens 或平台组件规范（如 Material Design 3），优先沿用既有体系，仅吸收本技能的布局降噪与真实渲染验收纪律。
- **职责衔接**：独立营销落地页使用 [landing-page-design](../landing-page-design/SKILL.md)；初版完成后的高视觉完成度精修与八维审查使用 [ui-design-quality](../ui-design-quality/SKILL.md)。

## 1. 布局与信息降噪

- 禁止大框套小框、嵌套卡片与多余分割线；改用排版对齐、留白距离与轻量表面明度差建立内容层级。
- 禁止无意义的营销口号、冗余副标题、装饰性标签和解释性长句；通过清晰的标签与动作名称让界面自解释。
- 按产品形态控制留白密度：
  - **内容展示型页面**：放大留白（组件内外边距约为常规页面的 `1.5` 倍），宁可留空也不塞满。
  - **效率工具／表格／后台**：保持紧凑清晰与合理信息密度，避免过度留白导致一屏有效信息过少。

## 2. 色彩与表面层级（90/10 原则）

- **色彩比例**：`90%` 画面面积保持黑、白、灰中性色，`10%` 面积仅使用 **1 种主强调色** 标出核心操作（主按钮）与关键激活态。
- **视觉禁令**：禁止渐变背景/文字、高饱和霓虹色、无目的毛玻璃以及多层复杂投影卡片。
- **亮色默认参考色阶**（若项目已有暗色模式或品牌色板，优先复用项目 Token）：
  - 页面底色 `#FFFFFF`，次级表面 `#F7F7F8`，细边框 `#E5E7EB`（`1px`）
  - 主文字 `#181818`（避免纯黑 `#000000` 在白底上的刺眼对比），次要文字 `#6A6A6A`，弱提示 `#9CA3AF`
  - 语义色（成功/警告/错误）仅用于状态指示与反馈提示，保持低饱和克制，禁止大面积高饱和铺底。

## 3. 排版、栅格与图标

- **中英文回退字体栈**：`"Geist", "Inter", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`；表格数字、金额、计时与指标强制开启 `font-variant-numeric: tabular-nums`，避免数值跳动错位。
- **三级字号阶梯**：
  - 页面主标题：`24px`，字重 `600`，行高 `1.3`
  - 区块标题：`18px`，字重 `600`，行高 `1.4`
  - 正文：`14px` 或 `16px`，字重 `400`/`500`，行高 `1.6`；辅助说明：`12px`–`13px`
- **间距栅格**：所有 `margin`、`padding`、`gap` 严格取 **4px 整数倍**（`4, 8, 12, 16, 20, 24, 32...`），禁止任意零散像素。
- **三档离散圆角**：小按钮/输入框等控件用 `8px`，容器/弹窗用 `12px`–`16px`，徽标/胶囊/头像用 `9999px`；嵌套圆角遵循同心关系（外圆角 ≈ 内圆角 + 内边距）。
- **图标规范**：遵循本仓库约定优先使用 **Lucide**；统一本体视觉尺寸 `18px`、描边粗细 `1.5px`，置于 `24×24px` 透明对齐框内居中放置。若项目明确指定其他图标库（如 Reicon），使用前必须先核对本地依赖或官方文档导出，严禁臆造图标名。

## 4. 交互组件、输入等价与状态闭环

- **复杂浮层严禁手写几何判定**：桌面端多级菜单、Dropdown、Popover 与 Tooltip 必须优先使用成熟无头组件库（如 Radix UI、Base UI、Ark UI 或 Floating UI 的 `safePolygon`），确保开箱具备开启/关闭延时、安全三角区、键盘方向键导航与 `Esc` 关闭，禁止让模型从零手写鼠标坐标三角形拦截逻辑。
- **次要控件降噪而非彻底隐藏**：列表或表格行内的次要操作平时以低对比度弱化显示，在 `hover` 或 `focus-within` 时提亮；触控设备（`@media (hover: none)`）保持可见或收拢至明确的操作菜单，确保键盘与触屏用户可达。
- **七态闭环**：凡涉及交互或异步数据的模块，按实际需求补齐 Hover、Active、Focus-visible（清晰可辨的焦点环）、Disabled、Loading（骨架屏或克制加载指示）、Empty（清晰空状态引导）与 Error（可执行恢复提示）。
- **动效克制**：仅用于明确状态过渡，统一使用 `150ms–200ms ease-out`，尊重 `prefers-reduced-motion`，禁止弹性晃动与入场炫技动画。

## 5. 防御性布局与真实渲染验收

- **编码防溢出**：按钮与导航标签添加 `whitespace-nowrap` 防止意外折行；Flex/Grid 文本容器必加 `min-w-0` 并设置合理的单行省略或换行规则。
- **计算值 ≠ 渲染值**：代码完成后不能只看 CSS 计算属性或编译通过就结束，必须通过真实浏览器打开目标页面并截图核对宽、窄视口，重点排查文字折行溢出、图标视觉偏心、浮层遮挡及 `4px` 栅格破坏，修正后方可交付；若当前运行环境无浏览器工具，需如实记录“浏览器视觉渲染未验证”。

## 模板与落地方式

1. 需要作为项目持久化约束时，复制 [项目初版模板与检查表](references/design-template.md) 中的模板代码块到目标项目根目录，保存为 `DESIGN.md`（或合并进项目 `AGENTS.md`）。
2. 按目标平台裁剪：桌面端／Web 完整保留；纯移动端页面移除第 4 条中的“桌面端多级菜单”规则，并保证可点击触控目标不小于 `44×44px`。
3. 下发页面开发任务时，先配置 CSS 变量／Tailwind Token、字体回退与图标库依赖，再编写业务组件，最后执行浏览器截图验收。

## 来源

启发并改编自雷电芽衣（`@ZacharyZhang`）文章《在做精细化UI前，最基础的让AI写出干净界面的前端规范》（[X 原文](https://x.com/ZacharyZhang/status/2125643199158817074) / [博客原文](https://zacharyzhang.com/blog/ai-frontend-design-rules)，读取日期 2026-11-26）。

本仓库在保留原作者“量化参数 + 负面清单 + 渲染验收”核心思路的基础上，进行了工程化改造：遵循本仓库 Lucide 图标约定、改用无头组件库替代手写安全三角区、补充中文字体回退栈与等宽数字、区分展示型与效率工具型留白密度、修正纯 hover 隐藏导致的触控/键盘不可达问题，并补全表面色阶、七态闭环与防御性布局约束。
