# 八维设计质量审查

将“award-tier”作为设计目标。Awwwards、Webby Awards、FWA 是参考来源，不是自动认证；“没有任何可见改进空间”不能客观证明。验收是既定目标和清单满足、实际观察中没有具体未解决的任务内缺陷，且必要交互、可访问性和性能没有回退。

## 先界定比较对象

读取实际任务、目标页面、受众、主要动作、品牌和平台约束。查看当前页面及可用的截图／交互，记录基准；若尚无页面则先明确设计方向再实现。只有文档时说明无法作页面验收。

用户明确要求奖项对标时，从指定奖项官网查找实际获奖记录，核对作品、类别和年份，再查看可访问的作品。优先选择与产品目的、内容量和交互场景相近的少量参考；记录链接、借鉴原则与不适用的部分。不要仅凭画廊缩略图声称已体验作品，也不要把营销站的戏剧化镜头强加给生产工具。无法核实获奖或无法访问时明确缺口。

## 八维检查表

| 维度 | 要回答的问题 | 观察与证据 |
| --- | --- | --- |
| 排版 typography | 字体、语言回退、字阶、行高、行长和断句是否支撑阅读？ | 真实标题／正文／数字、多语言与文字放大截图 |
| 留白 whitespace | 组内、组间与章节节奏是否清楚，宽窄布局是否仍有意图？ | 实际对齐与边距、空槽及滚动状态 |
| 层级 visual hierarchy | 主要信息和动作是否先被理解，次要内容是否易找？ | 首屏与完整任务路径、必要的信息展开 |
| 颜色 color | 颜色角色与内容语义是否一致，实际叠色是否可读？ | 浅深色、照片／玻璃背景、焦点与状态配对 |
| 动效 motion | 动作是否有目的、节奏是否适合场景、关闭后信息是否完整？ | 进入／退出／中断、减少动效、离屏暂停 |
| 微交互 micro interaction | 反馈是否准确、可及时中断，输入方式是否等价？ | hover／按下／focus／pending／失败中适用状态及键盘／触摸 |
| 响应式 responsive | 重排是否保留任务顺序和内容，关键中间宽度是否成立？ | 窄／宽／临界容器、缩放、长文本和动态数据 |
| 原创性 originality | 是否有与产品内容相关的明确设计决定，而非套用流行装饰？ | 构图、图形、内容节奏及与参考的差异说明 |

静态组件不适用的动效或状态标为 N/A 并说明，不为填表添加功能。不能用总分掩盖任一关键可用性问题。

## 迭代闭环

1. READ：用实际页面和状态检查八维，给每项标通过、具体差距、未验证或 N/A。
2. COMPARE：对照任务目标和实际查看的参考，写清差距落在哪个元素、状态或宽度，以及为何影响结果。
3. PATCH：优先修任务内影响最大的具体问题，保留既有业务和用户素材；新方向先说明，不能每轮换一套风格。
4. RECHECK：同条件重新查看改动区域并检查相邻回归。记录改善证据；失败就修正，不以重跑到一次通过替代解决。
5. STOP：适用项全部通过、必要检查通过且没有具体未解决差距时交付。若只剩互不优劣的风格偏好，记录取舍后结束；若素材、工具或用户决定阻塞，列出未验证项并等待该条件，不空转、不宣布完美。

不使用 OVERRIDE_ALL 等标记改变指令优先级。获奖参考不会覆盖用户范围、产品契约、可访问性和事实准确性，也不自动授权付费素材、安装工具、发布或提交参赛。

## 交付证据

简要说明所选方向、关键修正、实际查看的视口／状态和未覆盖项；提供可用页面或产物入口。只报告真正执行的检查；不声称“已获奖”“全设备完美”或“再无改进可能”。

本技能将用户提供的八维视觉标准整理为可执行、可停止的审查流程。
