# ui-knowledge-evidence

## 设计融合：证据优先于视觉叙事

可借鉴落地页“主张旁边给证明”的阅读结构：解释或关系摘要旁提供原文位置、材料身份和依据类型，详情按需展开但始终可追溯。空白、未加载、无依据和相互矛盾分别呈现，不能用逼真的案例姓名、数量、推荐语或装饰图补足缺证据的页面。

关系动画只表达已有选择、导航和加载变化，不把循环脉冲暗示成事实传播、因果成立或实时模型处理。演示数据需独立标识，不能混入用户知识图、人工审核结果或引用正文。

方法参考：[Elaya AI Design Skills](https://github.com/elayadesign/ai-design-skills/tree/38bbe5765600b9178b5395a823c9f6c8d2b8e730)；以上为面向本技能的适配，现有项目契约与用户明确要求优先。

## 输入与前置检查

从仓库根读取 AGENTS.md、apps/web/AGENTS.md 和 [设计系统](../../../docs/ui/DESIGN_SYSTEM.md)，只加载本次相关规范。读取 Resource/证据字段与 RelationshipDetails、ViewpointCards；辨认历史数据和失效来源。

## 执行

知识布局优化遵循[重点页面布局](../../../docs/ui/DESIGN_SYSTEM.md#priority-page-layouts)：左树定位、中央当前分类／局部关系、按需详情与证据。跨类入口必须展开到真实节点和双方路径／关系依据，不为减少卡片或连线只剩大类统计；深层紧凑呈现不能删层、多归属不能复制身份，主动隐藏与未完整加载仍可辨。默认不铺全局连线；已有对照视图和检查器按当前对象切换，避免常驻多重详情栏，关闭恢复原视角与焦点。

保持原文事实/背景/推断/人工标注与解释立场区分；展示双方、关系类型、原位置和真实来源；无证据明确说明。

知识页默认使用嵌套分类容器与独立局部关系探索，展示边界见 [设计系统](../../../docs/ui/DESIGN_SYSTEM.md) 的“知识嵌套分类与跨类对照”。容器表达导航包含，多归属使用同一身份的引用入口；跨类汇总必须可展开到实际两端与具体关系，不把整个大类当作关系端点。缺少中间路径时明确未完整加载，不补造分类。

显示隐藏与知识审核、检索授权分别维护；主动隐藏的对象不能因展开关联自动出现。只读浏览不创建模型解释，旧关系未记录依据类别时显示旧记录状态，不根据 UI 位置推定“参考框架关联”。更完整的参考书与 AI／Agent 协议仍按 TODO 验收，不把前端展示当作处理协议已经实现。

## 禁止事项

颜色迁移遵循[冷铂灰蓝的内容例外](../../../docs/ui/DESIGN_SYSTEM.md#platinum-gray-blue)：工具与检查器外观可用新主题，分类、关系类型、证据状态及用户保存颜色维持独立身份／映射，不按品牌灰蓝全局替换。关系或证据色须配文字／图例，浅深和强制颜色下能辨认；换色不改变支持／冲突、审核状态、隐藏偏好或引用正文，也不能把相同蓝色理解为同一关系。

禁止虚构来源、将区域重叠解释为因果、把多归属改成单父级，或截断关键证据正文。 维护原文件、公共 API 和人工元数据边界，不自动委派开发任务。

## 产物与验收

可追溯检查器、引用定位及旧/失效/无证据夹具。 同步 README；完成状态只在 TODO 记录。来源可定位；拒绝/接受独立于支持度；缩放不改图集合；纯查看不调用模型。

## 触发示例

- 应触发：“在知识详情展示完整证据与材料身份”。
- 不应触发：“优化线段相交算法”。
