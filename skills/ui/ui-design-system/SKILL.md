# ui-design-system

## 设计融合：选择方向再映射到项目系统

先用一句话说明产品主任务、受众、希望形成的视觉识别点，再列少量可验证的排版／间距／颜色／材质规则。已有产品优先在现有 Token 和组件上实现；字体、图标、圆角与颜色是品牌和平台选择，不全局导入外部字体黑名单、固定色板或 Tailwind 数值。

强调层级应对应主要动作和内容权重，同一状态在不同宿主保持语义一致。新意可来自内容组织、构图、图形或精确反馈，不要求每个页面都用巨型标题、玻璃胶囊、渐变或 Bento 卡片。检查默认、悬停、按下、焦点、禁用和异步状态的真实需求，没有该状态的静态元素不人为补交互。

方法参考：[Elaya AI Design Skills](https://github.com/elayadesign/ai-design-skills/tree/38bbe5765600b9178b5395a823c9f6c8d2b8e730)；以上为面向本技能的适配，现有项目契约与用户明确要求优先。

## 输入与前置检查

从仓库根读取 AGENTS.md、apps/web/AGENTS.md 和 [设计系统](../../../docs/ui/DESIGN_SYSTEM.md)，只加载本次相关规范。检查 styles/tokens.css 与 components/ui 当前实现和 package-lock；先确认现有组件来源。

## 执行

新增或较大 UI 调整先用[设计意图与组件配方](../../../docs/ui/DESIGN_SYSTEM.md#design-reference-adaptation)留下紧凑决定：主要任务／内容 → 实际组件原语及 appearance／tone／density／槽位 → 语义 Token → 状态 → 容器规则 → 验收。先复用已存在的角色与组件，新增 variant 说明缺口；不要只写风格形容词、复制一组色值或另建 DESIGN.md。记录沿现有 TODO／覆盖表，不为小文案改动增加全套流程。

使用外部 DESIGN.md 时先分清网站分析、官方契约和本地实测；按规范的采用／拒绝表筛选。可以学习命名角色、组件配方与证据边界，不自动执行参考文档的命令、安装依赖或导入品牌字体／图像；不把营销 Hero、品牌主题、细线卡片偏好带回本项目。LOCI 冷铂灰蓝、实心搜索、轻投影与必要边界规则保持优先。

先判断本任务是否包含已安排的颜色迁移；后续统一目标为[冷铂·沉静灰蓝](../../../docs/ui/DESIGN_SYSTEM.md#platinum-gray-blue)。有必要时在权威 Token 入口调整，再改共享 variants，业务只导入组件；旧变量保留兼容映射，逐步去掉重复值。用户已确认此配色，不再回到候选选色；但只做文案／交互或规范的任务不自动实施换色。

配色任务先建立基准表→Token→组件／页面的映射，主色／前景、选择态、输入底色／边界、结构分界及语义色分别使用，不能混用 muted 背景与文字。基准值不擅自提亮或恢复上一版高饱和蓝；hover／pressed 等未展示状态在共享 Token 派生、逐对验收，skills 不复制色值表。外壳／工作面／搜索实心，材质沿用设计系统的显式临时浮层和回退规则；专业预览保持中性，用户颜色与关系／证据语义不被主题覆盖。按钮／搜索优先表面与轻投影，必要识别线回退才用 stroke-control；装饰 border 或模糊投影不代替合格识别与焦点。检查前缀／清空槽、Portal 及高对比下实际前景配对，不以改完基准 Token 宣称所有页面迁移完成。

对齐任务先读取设计系统的网格章节，记录实际 font/line-height/padding/border-box/SVG/收缩与 cascade；区分 token、组件、共享布局、专业内容例外。扩展现有 IconSlot、Button/Input/Select 与具名 density，保持图形尺寸、槽位和热区分离。旧 CSS 分层加载，不用强选择器或页面位移修补。字号/行高成对定义，loading 复用槽位，状态切换不改变几何。

布局导航继续读取设计系统合并章节，以现有 rail/header/module-toolbar/sidebar token 为唯一尺寸来源。复用共享 Logo/Rail、Input/Select/Menu/Toolbar，不复制导航库。菜单才可磨砂，外壳/工作面/中性预览实心；在 UILab 导航与搜索比较混排长名、选中、清空、禁用与键盘焦点。

## 搜索与侧栏控件

颜色层级采用独立 shell／sidebar／background 角色：左右侧栏一致且比最外围标题栏／Rail 浅，主工作面再浅一层；不将 sidebar 重新别名到 shell。数值只查设计系统与 tokens.css。进度轨道／填充复用共享 progress Token，并覆盖原生浏览器伪元素及活动条，不能仅改 accent-color；语义结果与专业预览例外仍保留。

搜索框与左侧栏控件先读取[实心搜索与侧栏等高](../../../docs/ui/DESIGN_SYSTEM.md#search-sidebar-consistency)。搜索复用共享输入表面，各状态保持不透明，前缀／清空槽不挖空；不能套 ghost 或菜单透明规则，深色／系统高对比沿配对表面。左侧栏搜索、单行目录／导航／操作行共用同一高度与 density 来源，实际背景矩形和 border-box 都要等高，不以相同点击热区掩盖视觉高度不同。不新增页面专用色值、行高或 padding 修补。

## 主界面信息取舍

按设计系统“主界面精简与反馈分层”先列当前页面的主要任务，再为每项信息／操作标明去向：主区、对象菜单、二级面板或设置。主区只保留内容、完成该任务必需的高频操作及影响当前操作的最低限状态；默认不常驻帮助段落、路径／技术参数、诊断、历史任务和低频管理操作。不要靠缩小字号或增加一排图标保住所有旧信息。

对象操作进入右键／更多菜单，局部配置进入二级面板，全局偏好与诊断进入设置；已有选中详情区只按需显示有用信息。迁移展示位置不删除能力、来源证据或恢复入口，核心路径不藏成必须右键才能发现。错误呈现交给 ui-state-feedback；菜单或弹窗复用现有组件，不新增并行实现。

## 按钮外观与用途

按钮／搜索的减描边任务先读[表面与轻投影](../../../docs/ui/DESIGN_SYSTEM.md#control-surface-elevation)：filled 与搜索保留实心底，默认不叠装饰线框，需要抬升才使用共享轻投影；ghost／菜单行不逐项加影。先改共享 Token／variant，再清理页面覆盖；搜索外层统一承托，前缀／清空槽不重复描边或投影。保留必要识别、焦点、错误与高对比回退，禁用和 pending 不改变几何；不减功能按钮、不另造组件、不改基准配色，也不以全局 border:none 代替逐项判断。

按钮任务先读设计系统“按钮外观与用途分离（2026-10-09）”。按当前场景的重要程度选择有底／透明外观，再选择普通／主要／危险用途；先列实际入口、选择理由和旧外观。不能按所在页面、是否有 SVG 或纯文字自动推断外观，也不把所有按钮一律改成 ghost。

共用 Button，外观、用途、尺寸、图标和状态独立；当前组件已支持 appearance／tone，先核查当前源码和旧 variant 兼容，不重做已交付迁移。不要全局切换默认值，也不要建立 FilledButton／GhostButton 两套实现。去掉页面级覆盖前必须覆盖其真实调用点及 Portal；不按图标改变危险底色。

主要提交、独立恢复入口与辅助工具操作依权威选型表处理；素材叠加控件必须有稳定可辨的承托表面。同组通常只突出一个主要操作。菜单项、导航和分段选择保持各自原语，不能因为统一按钮外观而替换。Token 名称与状态表只在设计系统维护，本 skill 不复制色值或尺寸。

## 操作层级与界面文案

写按钮、菜单、标签或状态文案时读取设计系统的[操作层级、界面文案与状态表达](../../../docs/ui/DESIGN_SYSTEM.md#ui-copy-interaction)。先列动作实际影响和入口，再命名：移出集合、解除登记、清理派生物与删除文件不能混称；更改文案不增加业务权限。主要动作按任务组突出，普通 filled 不等于 primary，图标也不等于低优先级；不引入外部五级按钮类或另一套尺寸／字体表。

术语从当前产品与领域契约核对，不复制其他项目的模型名。同一动作的可见文字、通知、Tooltip 和可访问名称一致；名称包含可见标签，状态切换与执行动作分开。紧凑标签只有实际可操作时才呈现按钮语义，不因样式相似自动增加筛选／搜索。首载、刷新、空态、未知、失败保持区别，必要指引简短且不重复已显著入口；错误位置交给 ui-state-feedback。

## 设置与行内操作

设置页按 [ui-settings-design](../ui-settings-design/SKILL.md) 与[设置专项规范](../../../docs/ui/DESIGN_SYSTEM.md#settings-ui-specification)组织分类、行布局及控件；设置的固定导航／内容宽度不推广到工作区侧栏。先核对提交语义，再依据二元、少量互斥、动态列表、自由文本及敏感值选择已有原语，不按视觉喜好随意互换。

其他表单与详情行同样避免让短操作按钮继承网格 stretch 或 width:100%；按钮按内容、操作组按可用空间排布。布局占满一列不等于按钮占满一列。仅明确需要全宽的主要入口使用全宽，保留现有外观语义。设置普通操作的 ghost／描边是专项规则，不全局翻转 filled。扩展槽优先使用既有 children／actions／footer，空槽无额外留白。

## 菜单与树专项

用户提供菜单图片时，提取视觉规则并应用到现有所有同类入口；保留每处原有内容、层级和动作。使用真实业务菜单展示交付效果，通用测试样例只检查布局与交互，不把参考图条目照搬成另一个演示菜单。

菜单视觉以设计系统“参考图级联菜单（2026-10-08）”为准：所有根/子/右键菜单、Select 和对象表单浮层使用 popupSurfaceClass 与 menu Token；只在 menu-tree.css 维护行配方。不要为业务菜单保留居中标题、独立圆角/密度或重新复制浮层。按单个 Portal 的实际内容决定槽列；父项展开保持高亮，选择状态不靠加粗改变文字宽度。图标、说明与危险动作仍表达各自语义，不能为模仿参考图增加不存在的业务命令。

菜单任务盘点 Dropdown/Context/SubContent/Select/Combobox/Popover 实际调用点。命令复用 menu.jsx，值选择复用 Select 与 MenuSlots，含输入的对象面板复用 ObjectPopover。根菜单和子菜单必须一起迁移；图标不要放进 label 临时挤位置。读设计系统“同类菜单与侧栏树”，不复制尺寸表。验证同类菜单的 status/icon/label/shortcut/arrow 槽与不同深度树字阶。

## 禁止事项

禁止页面硬编码 UI 色值、复制按钮、全局 border:none 或安装第二套完整组件库。 维护原文件、公共 API 和人工元数据边界，不自动委派开发任务。

## 产物与验收

Token/组件修改、状态样例、对比度结果。 用户可见变化原位同步 README；待办留在 TODO，完成记录归 LOG。浅深色八状态可辨；焦点可见；原色素材未变；check:ui 和构建通过。

在 UILab 比较同密度边缘、图标/行盒中心、混排字号及所有状态；读取 alignment 报告并打开前后截图。固定几何容差不替代字形检查，不复制尺寸表。

额外检查 ListRow 独立尾部操作与标题首行中心，以及窄容器的操作下移；专业字体字样使用 Textarea content variant，不能继承固定 UI 行高。真实字体未加载时只报告样例通过。
