# 落地页设计

先让访客理解产品与下一步，再通过具体构图和细节形成识别度。适用于独立营销页、活动页与下载页；已有网站局部修改保留实际结构与品牌，不借技能扩大为全站重做。

## 从已有信息确定方向

从用户请求和项目读取主要受众、真实产品能力、访问来源、主要动作、可用素材和品牌约束。缺失且会改变方向的内容集中询问；可合理推断的说明假设后继续。不得自行编造产品承诺、价格、指标、客户名、评价或保证条款。

用一小段明确价值主张、视觉方向和页面主线。高意向下载页可以很短，复杂产品可用长叙事，比较页需要真实对照依据；无需每页都填满同一组章节。

## 内容和结构

- 首屏通常包含清楚的产品／结果说明、必要解释、一个主要转化动作和能说明产品的视觉。只有已有证明时才加入客户、指标或评价；没有就用可验证的产品演示，或省略。
- 中段围绕访客的理解障碍选择利益、机制、步骤、案例或对照。证明靠近对应主张，FAQ 只回答实际问题，不为达到条数编写内容。
- CTA 的文字和目的地一致。合法的辅助导航、登录和不同人群入口可以保留，视觉优先级清楚即可；不要删掉必要功能来维持“唯一按钮”。
- 结尾给出明确下一步。退款、无信用卡和随时取消只有业务确实支持时才能写。法律和隐私链接必须是真实页面，相关条款缺失时明确待补，不自动起草法律承诺。
- 演示／占位内容显式标注，在发布前替换或移除；禁止用更像真的小数或人名隐藏虚构。

## 视觉实现

按 [视觉系统参考](references/visual-system.md) 选择与品牌、语言和内容适合的字阶、间距、配色、图形及动作反馈；先复用项目 Token。不要机械禁用字体、图标、渐变或强制玻璃导航。原创性来自产品内容与明确构图，不来自叠加装饰。

以真实首屏内容确定视觉方向，再按需逐段实现，减少每轮全页重建。样式变更不更换技术栈或加入新的付费服务。宣传动画限于有叙事目的的视觉，产品截图不自动变成无限循环动画。

## 验证与交付

实际查看宽、窄视口与关键中间宽度，检查字形、换行、留白、焦点、触摸、菜单、表单和加载／失败状态。页面首屏内容与 CTA 默认可见；JS 或动画失败不隐藏正文，减少动效显示最终状态。

按任务决定搜索索引策略与真实 meta 内容，不默认给所有活动页 noindex；检查链接、语义标题、图片替代文本、favicon 和已有分享图。不得用自动补齐的评分／FAQ schema 声称页面不存在的信息。

高视觉要求时使用八维清单：排版、留白、层级、颜色、动效、微交互、响应式、原创性。记录具体差距、修正并查看结果；没有任务内明确缺陷时结束。报告已实现页面、实际检查和未验证项，不声称获奖或“再无改进可能”。
