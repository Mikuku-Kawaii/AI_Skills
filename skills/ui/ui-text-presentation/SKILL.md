# 前端文字呈现

让用户先看见当前任务的对象、关键值和即时动作，再按需读取上下文与细节。信息分级决定呈现优先级，不改变业务事实、权限、来源或用户原文。

## 入口与边界

先读取适用 AGENTS、[设计系统](../../../docs/ui/DESIGN_SYSTEM.md)的相关章节和当前组件实现。字号、行高、颜色、间距只消费项目现有 Token；本技能不建立第二份数值表，也不自动改造所有页面。

先确认当前任务、展示对象和实际动作，再为受影响内容列一份简短映射：信息 → 层级 → 默认位置 → 溢出／完整阅读方式 → 扩展槽。小改动可直接记录在既有任务计划，不另建报告或设计文档。

## 信息分级

| 层级 | 用户需要知道什么 | 常见内容 | 呈现原则 |
| --- | --- | --- | --- |
| 一级 Primary | 我正在看什么，现在最需要做什么 | 当前对象标题、核心数据值、主卡片内容、当前任务 CTA | 放在首要阅读路径；用既有标题／关键值字阶或适度字重建立重点，同一任务组避免多个竞争焦点 |
| 二级 Secondary | 如何理解、选择或操作这个对象 | 标签、次要按钮、单位、上下文、必要辅助说明 | 靠近它所解释的一级信息；通过分组、间距和正常可读的次级字阶支持理解，不与标题争抢 |
| 三级 Tertiary | 我需要核查哪些细节 | 时间戳、技术元数据、低频操作、折叠详情、调试信息 | 按当前任务移到元数据行、详情、菜单或设置；入口可发现，内容可完整读取，不堆在主要视线内 |

- 按任务而非字段名称机械分级：版本冲突时版本身份是决策依据；定位来源时路径可成为核心内容；历史浏览中时间可能是主信息。
- 主卡片不等于卡片内每段文字都是一级。每个局部任务保留清晰焦点，不把所有标题、标签、数字都加粗。
- 信息层级与 HTML 标题级别、按钮 appearance／tone 分开。不能用 `h3` 表示所有三级文字，也不能把所有 CTA 都设为鲜艳实心。
- 错误、未知、部分成功、授权限制等影响决策的状态必须可辨。详细原因可下沉，但不能隐藏唯一恢复入口、来源证据或把失败伪装为空。

## 字阶与阅读节奏

- 先用位置、分组和留白区分内容，再选择成对的字号／行高和必要字重；不通过连续缩小字号容纳更多信息。
- 同类信息跨卡片、跨页面保持语义角色一致。中英混排、数字和图标按实际字形／行盒校准，不为单条文案增加像素位移。
- 标签和值应能配对阅读；数字同时带必要单位、范围或口径。比较数据可用等宽数字和尾列对齐，正文按阅读方向起始对齐。
- 三级文字不是低对比文字。复用配对前景色，避免对整个文本容器降低 opacity；颜色区分必须有文字或其他可辨线索，浅深色及系统高对比都可读。
- 阅读顺序与 DOM 顺序一致；标题保持语义层级，字段有可访问名称，辅助说明通过现有组件关联，不拿 placeholder 代替标签。

## 文案密度与渐进展示

- 标题标识对象，正文说明内容，动作名称说明真实结果。减少重复前缀和无助于决策的技术解释，不擅自改写用户标题、正文、授权结论或证据。
- 辅助说明放到对应对象／字段附近；共通操作说明只在合适入口解释一次。低频技术细节下沉后保留返回与再次查看路径。
- 标题、列表名称可以省略，但要有可用的完整阅读路径；不能只依赖鼠标悬停或浏览器 title。按场景提供聚焦可读、详情或可展开内容。
- 正文、错误详情、路径和引用优先自然换行并支持必要的选择／复制。长单词、URL、混合语言不能把操作列推出容器，也不能全局强制逐字断开普通正文。
- 无数据、未读取、失败与未知分别表达；不把缺失值显示成零。加载和状态更新复用稳定槽位，避免按钮／标题因文案变化横跳；不为稳定布局预留整块空白。

## 配置说明的适配

设置页用 [ui-settings-design](../ui-settings-design/SKILL.md) 的标题／说明预算。单行标题与最多三行说明是设置专项，不全局裁切正文、引用或错误详情。其他 UI 同样先用一句说明表达作用／后果，较长依据通过可聚焦帮助或展开入口完整读取；必读风险和决策依据保留可见摘要，不能只缩小字号或放进悬停气泡。说明内有链接时不得被 clamp 裁掉仍进入隐藏焦点。

## 留余地：Slot / Children 扩展契约

可复用内容容器必须能通过 `children` 或有明确职责的槽位注入扩展部件，不把标题、说明、状态、正文和动作写死在容器内部。优先复用当前组件已提供的接口，不为单次需求建立通用页面配置引擎。

- 按实际需求选用 `title`、`description`、`leading`、`meta`、`actions`、`footer` 等具名槽；这些是设计示例，接入前核实当前 API，不要求一次提供全部槽位。
- 容器负责排布、间距和语义关联，调用方负责内容、状态与动作。可见内容与可访问名称分离时保持一致，不能把业务请求或权限判定藏进展示槽。
- 正文区域由内容与可用空间决定尺寸，使用 Grid／Flex 的弹性轨道、`min-width: 0` 和必要的换行；操作槽保持可用。窄容器可换行／重排，不能以固定宽高裁掉文字。
- “不写死固定宽高”针对内容容器，不禁止统一控件热区、图标槽、预览比例或受约束滚动视口。确需尺寸边界时使用现有 Token、容器／视口约束和明确滚动归属，不复制页面魔法数。
- 可选槽为空时收回它专属的空隙；加载／已知即将切换的状态需要保位时，只保留相应控件空间。新增徽标、第二段说明或尾部动作不能破坏标题与正文的阅读顺序。
- 插槽内容变长、缺省、异步更新或包含交互控件时，检查焦点顺序、键盘访问和窄宽度重排；槽位的可扩展性不授权增加新的业务操作。

示例：素材卡片以作品预览为一级；按当前产品约定在悬停、聚焦或选中时展示标题、尺寸与大小；技术路径放详情。详情容器可用正文 children、元数据槽和动作槽组合，而不靠定高截断新增说明。示例不覆盖用户后来明确指定的展示方式。

## 相称验收与协作

- 用当前任务检查是否一眼能识别对象、关键值和主要动作；标签是否贴近其对象，三级信息是否仍可找到。
- 对受影响容器核查短／长标题、中英混排、长路径、空槽及新增动作；文字放大、窄栏、浅深色和键盘焦点下无裁字、遮挡或丢失完整阅读入口。
- 真正改变页面时查看实际渲染和相称回归；只修改技能文档时校验格式、链接、触发边界即可，不把规范编写称为页面验收通过。
- 调整共享 Token／控件用 [ui-design-system](../ui-design-system/SKILL.md)；涉及长内容布局用 [ui-defensive-layout](../ui-defensive-layout/SKILL.md)；错误与异步反馈用 [ui-state-feedback](../ui-state-feedback/SKILL.md)；交互／可访问语义用 [ui-accessibility](../ui-accessibility/SKILL.md)。仅按本次实际变化加载，不全量触发。
